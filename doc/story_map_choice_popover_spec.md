# 스토리맵 "+" 버튼 — 선택지 생성 팝업 스펙

## 배경

`story_map_view.dart`의 노드 박스에 있는 "+" 핸들이 현재는 탭하면 바로 노드 에디터로
이동(navigate)하도록 잘못 구현되어 있음. 의도한 동작은 그 자리에서 뜨는 인라인 팝업으로
선택지를 만드는 것.

## 동작 정의

| 제스처 | 동작 |
|---|---|
| "+" 탭 (드래그 없음) | 그 자리에 인라인 팝업 오픈. 노드 생성/이동 없음. |
| "+"에서 기존 노드로 드래그 | 같은 팝업이 뜨되, 대상 노드가 이미 선택된 상태로 프리필. |
| "+"에서 빈 캔버스로 드래그 후 드롭 | 그 위치에 새 노드 생성 + 전체 노드 에디터로 이동 (기존 동작 유지, 변경 없음). |

## 팝업 UI 구성 (탭 시 기본 상태)

1. 제목: "선택지 만들기" (팝업 헤더, 별도 title bar 없이 카드 상단 텍스트로)
2. 텍스트 입력: placeholder "선택지 문구를 입력하세요"
3. 템플릿 칩 (텍스트 입력 채워주는 원클릭 버튼, 계속 수정 가능):
   - 다시 시도
   - 돌아가기
   - 계속하기
   - (주변을 살핀다 — 노드 에디터 쪽 칩과 동일 세트 공유)
4. 구분 라벨: "또는 기존 노드에 연결하기"
5. 기존 노드 리스트 (카드형, `ChoiceTargetPicker` 공유 위젯 재사용):
   - 각 카드: 굵은 글씨로 대상 노드의 본문 첫 줄 미리보기, 그 아래 흐린 글씨로
     "노드 {id} · {라벨}", 우측에 링크 아이콘
   - 카드 탭 → 현재 텍스트 입력값(비어있으면 기본값)으로 즉시 선택지 엣지 생성, 팝업 닫힘
6. 팝업 바깥 클릭 / 아무것도 선택 안 하고 닫기 → 아무 것도 생성되지 않고 취소

## 참고 이미지

Claude 대화에서 렌더링된 목업 참고 (`plus_button_popover_flow_mockup`):
- 노드 박스 우측에 "+" 원형 버튼
- 그 옆에 바로 붙어서 뜨는 팝업 카드 (텍스트 입력 → 템플릿 칩 → 구분선 → 기존 노드 카드 리스트)
- 하단에 "드래그해서 빈 곳에 놓으면 새 노드 생성" 힌트 텍스트로 탭과 드래그 동작이 다름을 표시

# "+" 드래그 → 빈 캔버스 — 새 노드 생성 스펙

## 동작

"+"에서 드래그를 시작해 빈 캔버스 위에서 놓으면(drop), 그 좌표에 새 노드가 생성되고
곧바로 통합 노드 작성 카드(아래 참고)가 열린다. 팝업이 아니라 실제 화면 전환/오픈.

## 생성 직후 상태

1. 새 노드 id는 기존 `suggestSequentialNodeIds` 로직으로 자동 부여 (예: 노드 7까지 있으면
   노드 8)
2. 작성 카드 상단 컨텍스트 라인에 어디서 연결되어 생성됐는지 표시:
   "노드 8 · 새 노드 (노드 5에서 연결됨)" 형태
3. 본문 텍스트에어리어는 완전히 빈 상태로 시작, placeholder "이 노드의 이야기를
   적어보세요" — 작가가 커서 두고 바로 타이핑 시작 가능
4. 소스 노드(예: 노드 5)에는 이 순간 이미 새 노드로 향하는 선택지 엣지가 생성된 상태
   (텍스트는 기본값이거나 비어있을 수 있음 — 저장 시점에 채워지지 않았다면 노드 작성
   카드를 닫을 때 선택지 문구를 마저 입력하도록 안내)

## 참고 이미지

Claude 대화에서 렌더링된 목업 참고:
- `plus_button_popover_flow_mockup` — "+" 탭 시 뜨는 선택지 생성 팝업 (위 섹션)
- `drag_to_new_node_mockup` — "+"에서 점선을 끌어 빈 캔버스에 놓는 순간(드롭 타겟 강조
  점선 박스 "여기 놓으면 새 노드 8 생성")부터, 놓은 직후 하단에 바로 열리는 통합 작성
  카드까지의 흐름

## 구현 시 체크포인트

- 탭과 드래그 제스처 구분 로직이 현재 어디서 처리되고 있는지 먼저 확인 (여기서 잘못
  연결됐을 가능성 높음 — `onTap`이 navigate를 부르고 있고 `onPanEnd`/`onDragEnd` 같은
  드래그 핸들러가 없거나 탭과 동일 콜백을 타고 있을 수 있음)
- `ChoiceTargetPicker`는 노드 에디터의 선택지 섹션과 스토리맵 팝업 양쪽에서 재사용되는
  공용 위젯이어야 함 (별도 구현 금지)
- 팝업은 `NodeEditSessionCache`에 스테이징하는 기존 저장 흐름을 그대로 따름 — 즉시
  Firestore에 쓰지 않음
- 새 노드 생성도 동일하게 세션 캐시에 스테이징 (임시저장/승인 요청 전까지 Firestore에
  안 쓰임) — 드래그 한 번으로 Firestore write가 바로 일어나면 안 됨
- 드롭 좌표를 그래프 레이아웃(graphview/Sugiyama)에 그대로 반영할지, 아니면 다음
  자동 레이아웃 재계산 시 자동 배치로 넘길지 결정 필요 — Sugiyama는 보통 자동 배치이므로
  드롭 위치는 "생성 트리거"로만 쓰고 실제 위치는 레이아웃 알고리즘에 맡기는 편이 자연스러움
