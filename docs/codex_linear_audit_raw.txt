선형 에디터 코드 감사 전체 기록
작성일: 2026-09-10
범위: 현재 작업 트리의 정적 코드 확인. 코드 수정·삭제·마이그레이션·배포는 수행하지 않았다.

기록의 출처
사용자가 지칭한 “방금 분석한 전체 답변”은 현재 대화 문맥에 제공되지 않았다. 저장소의 기존 doc/codebase_audit.md를 그 답변의 원문이라고 확인할 근거도 없다. 따라서 이 파일은 이전 답변의 원문 복사본이 아니라 이번에 현재 코드를 다시 확인한 전체 분석 기록이다. 이전 답변 원문을 복원했다고 주장하지 않는다.

판정
현재 작가는 팩 설정, 본문과 블록 작성, 미디어 선택, 수동 초안 저장, 승인 요청까지 진행할 수 있다. 그러나 순서/연결 불일치, 부분 저장·승인, 무료 경계의 이동 정지, 미저장 원고 복구 부재 때문에 한 작품을 안정적으로 처음부터 끝까지 제작 가능하다는 완료 판정은 내릴 수 없다. 현재 존재하는 draftNodes/nodes/liveSnapshot, LinearReader, SceneFrame, ReaderSessionController, StoryMediaSession을 살려 보완한다.

우선순위
P0: 원고 유실, 연결 파손, 실제 구매 진행 차단. 우선 수정.
P1: 제작 완료를 위해 필요한 미리보기, 연출, 읽기 완료, 오류 복구와 인수 검증.
P2: 기본 정책으로 출시 가능한 설정 보완과 작은 상태 표시 수정.
난이도는 1인 개발자가 관련 UI·저장·서버·검증을 함께 수정하는 상대 난이도다. 일정 추정치는 아니다.

확인된 기존 보호
- 작가 임시저장은 draftNodes, 독자 본문은 nodes의 liveSnapshot으로 분리되어 있다.
- 단일 노드 승인에서 해당 draft/live는 같은 batch로 갱신한다. 작품 연결 전체의 원자성까지 보장하지는 않는다.
- 서버 본문 게이트가 일반 비구매자에게 order 순서 무료 구간만 반환한다. 이번 지적은 전체 유료 본문 유출이 아니라 경계 UI/세션 처리 실패다.
- 배경 이미지 로드 실패에는 fallback과 signed URL 갱신 경로가 이미 있다.
- BGM/SFX 단독 미리듣기와 TTS 미리듣기는 이미 있다. 실제 작품 연속 재생 미리보기와는 범위가 다르다.

# 선형 에디터 완료 계획

## 선형 에디터 완료 기준

- [ ] 표시 순서, order, nextNodeId, 배경 상속, Reader 진행 순서가 일치한다.
- [ ] 추가·삭제·재정렬·승인 실패에도 초안과 공개 체인이 각각 유효하다.
- [ ] 수동 임시저장과 새로고침 복구가 가능하고 취소/실패로 원고가 사라지지 않는다.
- [ ] 미저장 작품을 실제 Reader로 처음부터 끝까지 미리보고 모든 연출을 확인한다.
- [ ] 비구매자는 허용 구간만 읽고 구매 후 같은 위치에서 이어 읽는다.
- [ ] 1노드/단면/펼침 작품 모두 읽기 완료와 이어읽기를 정확히 저장한다.
- [ ] 미디어 누락을 작가에게 알리고 복구 가능한 오류로 본문 읽기가 막히지 않는다.
- [ ] 대표 작품 1편의 생성→제작→복구→미리보기→승인→구매→완료 인수 시나리오를 통과한다.
- [ ] P0/P1을 완료한다. P2는 기본 무료 한도 3을 유지하는 범위에서 후속 처리할 수 있다.

## P0 문제 목록

### P0-1 순서·추가·재정렬·ID 변경의 연결 일관성

- [ ] 수정 완료
- 관련 파일: `lib/admin/pages/story_tab_view.dart`, `lib/admin/widgets/node_editor.dart`, `lib/admin/widgets/story_node_sidebar.dart`, `lib/admin/widgets/story_map_view.dart`, `lib/reader/linear/linear_reader.dart`, `lib/core/story/background_image_inheritance.dart`
- 문제 원인: _handleReorder는 order만 변경한다. Reader 시작점·페이지 번호·배경 상속은 order, 이동은 nextNodeId 기준이다. 추가 시 저장된 existing에서 끝 노드/order를 찾으므로 연속 미저장 추가를 반영하지 못한다. 신규 ID 변경은 캐시 키만 이동하고 기존 연결을 갱신하지 않는다.
- 수정 방향: 선형 팩은 표시 순서를 기준으로 order와 nextNodeId를 함께 생성하는 작은 순수 함수를 둔다. 서버 초안에 캐시를 덮어쓴 목록으로 추가·재정렬을 계산한다. ID는 생성 후 고정한다. 수동 다음 페이지/맵 연결 변경은 선형에서 제한한다. 기존 불일치 작품은 진단 결과와 정렬 결과를 보여주고 명시적 적용으로 정리한다.
- 영향 범위: 선형 목록·배경 상속·페이지 번호·맵. interactive 선택지 편집에는 적용하지 않는다.
- 테스트 방법: A→B→C를 C,A,B로 재정렬해 C→A→B→null 확인. 미저장 3회 추가, 동순위·순환·고아·없는 대상 검증. 저장/재접속 후 동일 순서.
- 난이도: 중간

### P0-2 삭제·저장·승인 사이의 연결 안정성

- [ ] 수정 완료
- 관련 파일: `lib/admin/pages/story_tab_view.dart`, `lib/admin/data/admin_story_repository.dart`, `lib/admin/pages/approvals_tab.dart`, `firestore.rules`
- 문제 원인: 단건/일괄 삭제는 들어오는 연결을 복구하지 않는다. 생성 시 이전 노드와 새 노드는 순차 저장한다. approveNode는 한 노드의 draft/live만 원자적으로 갱신하고 일괄 승인도 단건 반복이어서 공개 체인이 중간 상태를 노출한다.
- 수정 방향: 삭제 후 남은 순서로 연결을 재생성하고 관련 초안 변경을 한 묶음으로 저장한다. 승인 시 변경 후 공개될 전체 체인을 검증하고 연결 변경에 필요한 생성·수정·삭제를 함께 commit한다. 기존 draftNodes/nodes 구조와 승인 권한을 유지한다. 지원 한도를 넘는 묶음은 사전 차단하고 연결 변경을 임의 분할하지 않는다.
- 영향 범위: 승인 대기함·반려/삭제 취소·공개 Reader·보안 규칙. 내용만 고치는 기존 흐름은 유지한다.
- 테스트 방법: 처음/중간/끝/연속 구간 삭제, 신규+공개 혼합, 반려·취소, 쓰기 실패를 시험한다. 실패 전후 공개 체인이 온전하며 부분 승인으로 연결이 끊기지 않아야 한다.
- 난이도: 높음

### P0-3 임시저장·복구와 저장 중 편집 보호

- [ ] 수정 완료
- 관련 파일: `lib/admin/data/node_edit_session_cache.dart`, `lib/admin/pages/author_tool_page.dart`, `lib/admin/pages/story_tab_view.dart`, `lib/admin/widgets/bulk_node_writer.dart`
- 문제 원인: NodeEditSessionCache는 메모리 Map뿐이다. _saveDraftForNode는 성공 전에 dirty=false로 바꾸고 await 후 캐시를 제거하여 저장 도중 추가 편집도 제거할 수 있다. 삭제 경로는 확인/성공 전에 캐시를 제거한다. 일괄 원고는 위젯 컨트롤러에만 있다.
- 수정 방향: UID/packId로 분리한 버전 있는 로컬 복구본을 디바운스로 저장한다. 수동 서버 임시저장은 유지하고 저장한 스냅샷과 현재 편집 버전이 같은 경우만 캐시를 정리한다. 실패/삭제 취소 때 원고를 유지하고 저장 상태·복구 선택을 표시한다. 서버와 충돌하면 자동 덮어쓰기하지 않는다.
- 영향 범위: 로그아웃/계정 전환·팩 전환·전체 저장·삭제 UI. 로컬 저장에는 미디어 파일 대신 참조 ID만 보관한다.
- 테스트 방법: 입력 후 새로고침/재실행, 일괄 원고 탭 전환, 오프라인 저장 실패, 저장 중 추가 타이핑, 삭제 취소, 다른 계정 접근 차단을 확인한다.
- 난이도: 중간

### P0-4 일괄 작성 취소·실패·기존 작품 이어붙이기

- [ ] 수정 완료
- 관련 파일: `lib/admin/widgets/bulk_node_writer.dart`, `lib/admin/pages/story_tab_view.dart`, `lib/admin/data/admin_story_repository.dart`
- 문제 원인: _handleBulkSave의 확인 취소도 정상 Future<void> 반환이다. 호출자는 원고를 지운다. 예외 시 _saving을 복구할 finally가 없다. 신규 묶음 내부만 연결하고 기존 마지막 노드를 연결하지 않으며 ID 예약에 캐시를 포함하지 않는다.
- 수정 방향: 저장 결과를 성공/취소/실패로 반환하고 성공일 때만 입력을 비운다. try/finally로 저장 상태를 복구한다. P0-1/2의 목록·연결·묶음 저장을 사용하고 재시도에 같은 초안 ID를 유지한다. 임시저장과 승인 요청을 분리한다.
- 영향 범위: 한 번에 쓰기·ID 생성·전체 승인 요청.
- 테스트 방법: 승인 확인 취소 후 원고 유지, 저장 오류 후 재시도, 미저장 노드와 ID 충돌, 기존 작품 뒤에 일괄 추가, 중복 클릭을 확인한다.
- 난이도: 중간

### P0-5 무료 미리보기·구매 경계

- [ ] 수정 완료
- 관련 파일: `lib/reader/linear/linear_reader.dart`, `lib/reader/shared/data/story_reader_repository.dart`, `lib/reader/shared/story_media_session.dart`, `functions/src/secure_reader_nodes.ts`, `functions/src/secure_story_media.ts`, `lib/reader/shared/paywall.dart`
- 문제 원인: 서버는 승인본을 order 기준 N개만 반환한다. _goToNext는 대상이 없으면 구매 검사 전에 return한다. 구매 성공 후 본문 재조회도 없다. repository는 access를 로그로만 사용하고 publishedNodeCount를 세션에 전달하지 않는다. N=0은 빈 작품 안내로 이어진다.
- 수정 방향: access·전체 개수·경계 정보를 세션에 보존한다. 제한에 의한 미수신과 실제 연결 오류를 구분하고 경계에서 구매창을 연다. 구매 성공 후 본문/미디어를 재조회하고 원래 대상에서 이어간다. 방문 횟수 대신 서버가 허용한 노드 집합을 기준으로 단면·펼침·자동 진행 모두를 검사한다.
- 영향 범위: 구매 UI·Reader 세션·전체 페이지 표시. 서버의 본문/미디어 권한 검사는 유지한다.
- 테스트 방법: 일반 비구매 계정으로 N=0/1/3, 경계 클릭·TTS 자동 진행·펼침·구매 취소/성공·재접속 시험. 유료 본문/미디어가 구매 전에 응답되지 않는지 확인한다.
- 난이도: 높음


## P1 문제 목록

### P1-1 편집 중 작품을 실제 Reader로 미리보기

- [ ] 수정 완료
- 관련 파일: `lib/admin/pages/story_tab_view.dart`, `lib/admin/widgets/node_editor.dart`, `lib/admin/widgets/bulk_node_writer.dart`, `lib/main_scene_frame_preview.dart`, `lib/reader/linear/linear_reader.dart`, `lib/reader/shared/scene_frame.dart`, `lib/reader/shared/data/story_reader_repository.dart`, `functions/src/secure_story_media.ts`
- 문제 원인: 에디터에는 작품 Reader 미리보기 연결이 없다. Bulk 미리보기는 분할된 텍스트 카드이고 별도 main_scene_frame_preview는 고정 데모다. 일반 Reader API는 작가에게도 공개 승인본만 반환한다. 미디어 게이트도 공개 노드 참조 기준이다.
- 수정 방향: 초안+캐시를 Reader 모델로 변환하는 어댑터와 LinearReader의 제한된 데이터/부수효과 주입 지점을 추가한다. 동일 LinearReader/SceneFrame으로 처음부터·현재 위치 미리보기를 제공한다. 작가 권한으로 초안 미디어를 해석하고 미리보기 중 조회수·진도·실구매·개인 설정 저장은 막는다. 초안 전체 보기와 비구매 경계 시뮬레이션을 구분한다.
- 영향 범위: Reader 생성자·미디어 해석·설정/진도 저장·작가 화면. 공개 API에 초안을 섞지 않는다.
- 테스트 방법: 미저장 본문/블록을 미리본 뒤 승인본 Reader와 모바일·데스크톱 결과 비교. 미리보기 종료 후 조회수/진도/설정 불변, 타 작가 접근 불가 확인.
- 난이도: 높음

### P1-2 배경·BGM·SFX·화면 효과의 연속 미리보기

- [ ] 수정 완료
- 관련 파일: `lib/admin/widgets/node_effects_editor.dart`, `lib/admin/widgets/bgm_picker_field.dart`, `lib/admin/widgets/sfx_picker_field.dart`, `lib/reader/shared/reader_session_controller.dart`, `lib/reader/shared/scene_frame.dart`, `lib/reader/linear/linear_reader.dart`, `lib/core/story/background_image_inheritance.dart`
- 문제 원인: BGM/SFX 선택기의 단독 재생은 playSfx여서 BGM 상속·전환을 검증하지 못한다. 펼침은 두 노드 본문을 합치지만 effects/sfx와 visitNode는 왼쪽 노드 기준이다. 임의 위치에서 BGM 상속으로 진입하면 이전 노드의 트랙 대신 팩 기본값을 쓴다.
- 수정 방향: P1-1에서 기존 효과 엔진과 세션 컨트롤러를 재사용한다. 현재 위치 미리보기의 초기 BGM은 앞선 순서의 지정/무음을 계산한다. 1차 완료 범위에서는 양쪽 중 노드별 연출이 있으면 단면으로 표시해 오른쪽 효과 누락을 막는다. 효과 재실행과 종료 시 오디오 정리를 제공한다.
- 영향 범위: 실제 Reader 펼침 조건·BGM 이어읽기·전역 AudioService. 효과 엔진 재작성은 피한다.
- 테스트 방법: 배경 기본/상속/개별, BGM 지정→상속→무음→재지정, 볼륨, SFX, blackout/shake/flash를 순서대로 시험. 오른쪽 노드에만 효과가 있는 펼침과 종료 후 오디오 확인.
- 난이도: 중간

### P1-3 읽기 완료 처리

## 실제 작업 순서

1. P0-1: 순서/연결 불변식과 순수 검증 함수부터 작성하고 추가·재정렬·ID 변경 경로를 통일한다.
2. P0-2: 구조 변경의 초안 저장·삭제·공개 승인 묶음을 구현하고 실패/반려를 검증한다.
3. P0-4: 일괄 원고의 취소/실패 유실을 막고 기존 작품 이어붙이기를 연결한다.
4. P0-3: 편집 버전별 저장 성공 처리와 로컬 복구를 적용한다.
5. P0-5: 서버 접근 정보 보존, 구매 경계 표시, 구매 후 본문/미디어 재조회를 구현한다.
6. P1-3: 방문/완료 기록을 통일하고 1노드·펼침 완료를 수정한다.
7. P1-4: 미디어 누락 진단, 부분 실패 처리와 URL/오디오 재시도를 정리한다.
8. P1-1/P1-2: 실제 Reader 기반 초안 미리보기와 배경·오디오·화면 효과 검증을 연결한다.
9. P1-5: 제작 완료 검사와 대표 작품 인수 시나리오를 통과시킨다.
10. P2-1/P2-2: 무료 구간 설정 연결과 flash 상태 표시를 마무리한다.


검증 범위와 한계
- 위 원인은 파일 구현과 호출 경로로 확인한 정적 분석 결과다. 실제 Firebase 데이터, 배포된 규칙/함수, 브라우저 재생 환경은 실행 검증하지 않았다.
- 문서 작성 요청이므로 앱 실행·자동 테스트·서버 호출은 수행하지 않았다. 각 테스트 방법은 수정 후 통과해야 할 기준이다.
- 기존 테스트 파일은 카운터 예제이며 이를 선형 제작 흐름의 검증 근거로 사용하지 않았다.
- 별도 작품 “연재 완결” 상태는 현재 PackSerializationStatus의 공개 승인 상태와 다르다. 이번 계획에 새 상태 체계나 데이터 마이그레이션을 넣지 않았다.
- 공개 승인 묶음의 크기 제한은 기존 Firestore/규칙을 실제 구현 시 검증하고 명시적 지원 한도를 정한다. 대규모 버전 저장소 재작성은 선행하지 않는다.
